# Working rules for this project (for any agent)

The user's standing preferences are in `memory-export/` (copied from the Claude memory directory; `MEMORY.md` is the index). The ones that matter most: decide and edit instead of offering option menus; ask before every push and use `--force-with-lease=<branch>:<old sha>` for force-pushes; push to origin only; every PR targets 4.1 with a branch starting `4.1-`; PR text in a fenced block, written against upstream/4.1, never hard-wrapped, no Jira; capitalise after a colon; no unearned negation; base case first, then variants; never write "databag" (say settings); a status's transitions live in the operation that changes it; never glue two facts with different subjects using ", and" (split them or name the relation; full rule in `page-recipe.md`); check every docs builder (html and latex); reviewer-driven fixes go in separate commits; check the decision record (ggarch HANDOFF, SESSIONS, ADRs, the plan) before reopening a settled design question; read source pages in full. The agreed page form rules are at the end of this file; the router for a new chat is `HANDOFF.md`.

## Session rules (standing)

- **Restart the live preview in every session (user, 2026-10-21, session 92).** The server dies with its session. Start it from the PR worktree: `cd ~/git/misc/juju-tutorial-diagrams/docs && source ~/git/misc/docs-venv/bin/activate && sphinx-autobuild --port 8003 --host 127.0.0.1 . _build -c . -d .sphinx/.doctrees -b dirhtml -j auto -D llms_txt_enabled=0 --ignore '_build/*' --ignore '.sphinx/*'`. Port 8002 is the old pilot-tree preview (`~/git/misc/juju-v2-preview`, never push); 8003 is the PR tree. Verify a reference page answers 200 before relying on it.

- **Give the user a link to the live preview whenever there is something to look at (user, 2026-10-30, session 103).** A changed page, a held diff, a new figure: the message names the page and carries its URL (`http://127.0.0.1:8003/<page-path>/`). The preview is the review surface; do not describe in prose what the user can open.

## Page form rules agreed with the user (apply to every entity page)
Basic facts in the lede, in plain sentences, ending with multiplicities; lede one level above everything. No metalanguage ("below", "this page covers", "these errors"); inline "see X" pointers are fine. One topic per paragraph, sections add and never repeat; one home per fact, mentions link. Diagram first beneath its section title, caption stands alone, bullets use the diagram's chip names. Rules and errors nest under the record or operation they constrain (errors in operations also nested items; no padded tables for retrievable facts). Reference headings nominal and carry the entity name. Cross-reference every jargon term at first mention; explain our own terms in place. Client-agnostic: platform fact first, CLI or Terraform only as an example; operations with sequences stay in the reference as the client-agnostic home, how-tos point to them. No cardinality numbers on chip diagrams; state multiplicities in caption and lede. docs/ content = every fact observable at a named user-facing interface (operator, client developer, charm developer) plus spanning facts no single package can state; local developer-only facts stay in `doc.go`, schema comments and CONTRIBUTING. Do not name Go watcher methods in docs/: state the trigger semantics (the artifact's exposure tier decides inclusion).
